# Alifba

Русскоязычная демонстрационная витрина. Цены, заказы, карточная оплата и обратная связь работают в режиме показа. Корзина хранится в браузере. Сборка использует Node.js 24.

## Локальный запуск

```sh
npm ci
npm run dev
```

Откройте http://localhost:3000. Проверка типов: `npm run typecheck`.

## Просмотр статической сборки

```sh
npm run preview
```

Команда пересобирает `out/` для корневого URL и запускает локальный HTTP-сервер через Python 3. Откройте http://127.0.0.1:4173/ и оставьте терминал запущенным на время просмотра. При открытии `out/index.html` через `file://` браузер ищет стили, изображения и скрипты по абсолютным путям файловой системы.

## Наполнение

- `lib/products.json` содержит товары. `id` — стабильный артикул, `slug` — адрес страницы, `price` — целое число в копейках, `image` — имя файла в `public/media`. Обязательные поля `description` и `characteristics` содержат описание и характеристики. Объект `en` содержит английские `name`, `description` и `characteristics`. Добавляйте `ozonUrl` только после проверки соответствия товара конкретной карточке на Ozon.
- `lib/shop.ts` содержит события, адреса, соцсети, слайды большого баннера, выбранную новость для маленького баннера и общую ссылку `sharedOzonUrl` для товаров без индивидуального `ozonUrl`. Файлы изображений лежат в `public/media`. Исходный архив остаётся в `original-makeup`.
- Две архивные карточки событий основаны на баннерах старого сайта. Иллюстрации читательского клуба и акварели сгенерированы для демонстрации. Часы работы и телефоны в витрине взяты из архива, перед коммерческим запуском их нужно обновить.

## Языки и навигация

Русские страницы доступны по текущим адресам, английские — под `/en/`. Словарь интерфейса находится в `lib/i18n.ts`. Переводы событий и адресов лежат рядом с русскими данными в `lib/shop.ts`. Новые товары добавляются в одну ленту на главной в порядке записей `products.json`.

Поиск `/search/?q=...` сопоставляет русские и английские названия товаров и заголовки событий. Товары в результатах разбиты по 20 на страницу. Старые ссылки `/catalog/` и `/catalog/<category>/` направляют на главную, запросы `q` — на поиск.

Переводы подготовлены заранее. Описания товаров написаны для текущего макета на основе названий, назначения изделий и содержания книг. Для уточнения аннотаций использованы [АСТ](https://ast.ru/book/shesterka-voronov-867210/), [Эксмо](https://eksmo.ru/book/isadora-moon-kniga-1-u-n--ITD919229/) и [сайт Джеймса Клира](https://jamesclear.com/atomic-habits).

## GitHub Pages

В репозитории откройте **Settings → Pages**, выберите **GitHub Actions**, затем вручную запустите **Publish demo to GitHub Pages**. Workflow соберёт `out/` и возьмёт префикс проекта из настроек Pages. Публикуемый артефакт содержит только витрину и нужные ей ресурсы.

Для локальной проверки вложенных маршрутов:

```sh
STATIC_EXPORT=1 NEXT_PUBLIC_BASE_PATH=/alifba npm run build
# Разместите содержимое out/ в каталоге alifba/ статического HTTP-сервера.
```

## Node.js за Nginx

Для сборки в корневом пути оставьте `STATIC_EXPORT` и `NEXT_PUBLIC_BASE_PATH` незаданными.

```sh
npm ci
npm run build
npm run start -- --hostname 127.0.0.1 --port 3000
```

Держите процесс запущенным через systemd. В HTTPS-конфигурации Nginx проксируйте запросы к Next.js:

```nginx
location / {
    proxy_pass http://127.0.0.1:3000;
    proxy_http_version 1.1;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
}
```

Изображения обслуживаются из `public/media`. Коммерческие операции, синхронизация контента, админка и CRM требуют серверной реализации.
